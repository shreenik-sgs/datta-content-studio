## Schema and API mapping

- Core `0109_weekly_guidance.sql`: collection heads, immutable revisions, canonical item/provenance references, immutable approval/source fingerprints, idempotent receipts, world-consistency triggers, audit/outbox use, and seven OFF switches. Only immutable definition bytes are cached; heads, scope, time, permissions and canonical availability are checked fresh. Shared responses are private/no-store so a centre or member result cannot leak through a CDN cache.
- Core `0110_datta_circle_defaults.sql`: canonical centre/campaign/event source references and unique world keys for default circles. Provisioning is a deliberate idempotent seed/CLI operation, not a boot migration. It creates no membership, invitation, notification or automatic consent.
- Hub `0010_medical_prism.sql`: extends the existing append-only activation revision action constraint with `EDITED` and `DESTINATION_VALIDATED`. It creates no parallel analytics database.
- Admin page: `/admin/weekly-guidance`; API: `GET/POST /api/v1/admin/weekly-guidance`, with strict discriminated commands, same-origin/bearer protection, bounded request bodies, current role/flag checks, independent approval, and revision CAS.
- Read API: `GET /api/v1/home/guidance/active?lang=...`, guest/public or authenticated scope. Canonical entries use `/content/room/{UUID}`, `/content/event/{UUID}` and `/content/seva/{UUID}` as supported by the existing source. Specific social CTA links use `/s/{opaqueToken}` and preserve exact canonical intent through authentication.

## Local operations, analytics and rollback

The existing local bridge, signing keys and event spool are used. Relevant controls are `EXPERIENCE_RETURN_ENABLED`, `DISTRIBUTION_LINKS_LOCAL_ORIGIN`, `DISTRIBUTION_CORE_ORIGIN`, `DISTRIBUTION_DESTINATION_KEY`, `DISTRIBUTION_LINKS_ENABLED`, `DISTRIBUTION_LINKS_STAGE`, `DISTRIBUTION_SOCIAL_LINKS_ENABLED`, `DISTRIBUTION_LINKS_CACHE_ROOT`, `DISTRIBUTION_LINKS_KEY_ID`, `DISTRIBUTION_LINKS_PUBLIC_KEY_FILE`, `DISTRIBUTION_LINKS_PRIVATE_KEY_FILE`, `DISTRIBUTION_LINKS_EVENT_ROOT`, and `DISTRIBUTION_LINK_JOBS_ENABLED`. Keys/tokens are runtime secrets; never copy values into this receipt. The reviewed resolver and refresh jobs explicitly require local TEST configuration. The separate **legacy Seva link service on port 3066 remains production-locked**; this work does not relax it.

Guidance publication uses the existing `platform_events` outbox with a stable collection/version/world dedupe key and `fannedOutAt` set for analytics-only handling. It sends no notifications. Existing content event contracts carry first-party observations. `content_started` observes actual supported player playback, and canonical accepted practice outcomes remain governed by the unchanged counting rail. Client/API content summaries omit playback media references; only the authorized canonical player receives the media it needs. Provider reach/views remain separate. Do not report client clicks or completion signals as accepted ledger outcomes, invent unique-return counts, or combine provider views with first-party totals. Production producer adoption, consent/privacy thresholds and reconciliation remain the R6 gates described in `R6-analytics-readiness.md`.

The measured/local contracts bound revocation and diagnostics: core feature reads cache for at most five seconds, signed resolver records expire after 30 seconds, and the resolver gives durable event append a 25 ms budget before returning content. An attribution ID is present only when durable append succeeds in time; disk-full or failed writes cannot promise attribution and produce a generic operator log. Collector outages use the bounded spool (at most 10,000 files, 4,096 bytes each; drain batches of 25 every two seconds) and seven-day queued delivery with idempotent event UUIDs. A queued event must have occurred within 30 minutes of its exact canonical tracked receipt. Local privacy evidence `docs/distribution/evidence/content/hub-social-lineage.json` contains one destination validation, four tracked resolves and one joined landing; actor IDs are null and it contains no email, IP, raw token, session or referrer. These counts are fixture observations, not unique-return metrics. Seventeen placement definitions/manual exports do not mean 17 adopted providers or public sends.

Operational checks should distinguish destination failures from attribution failures: monitor resolver error/fallback reasons, signed-cache freshness, pending event spool and drain failures, destination-validation failures, approval/source mismatches, and guidance API availability. A destination may still succeed while analytics retries. Do not put confidential bodies or full tokens in diagnostic logs. No new synchronous AI call is introduced in a request.

Rollback is operational:

1. Set the seven switches OFF; restore the prior Home while retaining collection/version/provenance and attribution history.
2. Disable the new tracked-social bridge/resolver controls and stop the dedicated link refresh jobs; preserve the event spool for a deliberate replay/reconciliation decision. Keep any legacy Seva service's existing lock unchanged.
3. Read back the switch states, confirm guided sections/new tracked entry are unavailable, and exercise the canonical legacy route and existing V3.2 Home. Recheck that pending attribution is visible rather than silently discarded.
4. Retain additive tables and immutable history. There is **no practice-ledger rollback, deletion or compensating count generated by this feature rollback**. No full seed or production administrator login is needed.
