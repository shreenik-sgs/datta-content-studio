## Reproducible Android acceptance

The dependency-free instrumented runner is in `tests/mobile-native/android/`. It compiles against the installed Android SDK and signs only with the generated project's debug keystore. It refuses physical-device serials, non-local preview databases, and identities outside `@example.test`. Credentials are read from a private local configuration file and are not printed. The runner redacts password values from accessibility dumps.

Build the app with `EXPO_PUBLIC_API_URL=http://127.0.0.1:3020`; embed the Android bundle before `assembleDebug`, install the APK on a disposable/read-only emulator, and reverse its local port 3020 to the isolated core preview. Then run:

```sh
ANDROID_HOME=/path/to/Android/sdk \
MOBILE_QA_ANDROID_SERIAL=emulator-5560 \
MOBILE_QA_CONFIG=/private/path/to/preview.json \
node tests/mobile-native/android/run.mjs tests/mobile-native/android/goals.json
```

Run `sign-in.json` first only when the generated fixture is signed out. The goals and enrollment scenarios expect the preview fixture to have an active personal goal. `large-font.json` validates 200% type and scrolling; `enrollment.json` ends the fixture goal and enrolls a new one. `flag-off.json` expects the six nurturing flags already disabled in the disposable preview; restore their previous stages afterward. Evidence is written to a fresh temporary directory and its path is reported. An unsuccessful assertion exits nonzero. The runner is a local QA tool, not bundled application code.

The harness follows the official [UiAutomation](https://developer.android.com/reference/android/app/UiAutomation) and [AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo) APIs. Keyboard insets follow the [React Native ScrollView contract](https://reactnative.dev/docs/scrollview#automaticallyadjustkeyboardinsets).

After the initial 3 October evidence collection, the task-owned simulator, read-only emulator and temporary Metro listener were stopped. The local-only embedded JavaScript bundle and its generated Android resources were archived outside the native source tree so a future ordinary build cannot accidentally include the QA backend. Core/Hub preview services were left running. After the 4 October keyboard recheck, Dynamic Type was restored to `large` and confirmed with `simctl ui content_size`; the task-owned simulator was shut down successfully. No feature flags were changed, and the core/Hub preview services were left intact.
