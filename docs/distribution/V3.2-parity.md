# V3.2 additive implementation parity

Sources: Master Platform Blueprint v3.1, its release plan and implementation gap map, and SGS_Datta_Sannidhi_V3_2_Codex_Handoff.docx (3 October 2026). V3.1 remains authoritative; the handoff is an additive delta.

| Area | Existing capability | Disposition |
| --- | --- | --- |
| Identity and permissions | Database sessions, role assignments, scoped Hub grants | Reuse; owner-only nurturing and language-scoped editorial review |
| Feature flags | Core feature_flags and OFF/TEST/STAFF/CENTERS/EVERYONE audience rules | Reuse registry and administrative controls; twelve additions default OFF |
| Practice accounting | Append-only view_entries, saved local entry_date, compensating corrections | Reuse exclusively; projections never grant canonical credit |
| Maha Sankalpa pledges | Append-only campaign pledges which cannot pause/cancel | Preserve; separate personal goal enrollment with immutable template and state history |
| Home and mobile | Web home, native home, practice catalogue, existing live overlays and SGS Posts | Add optional inline nurturing, preserving existing catalog and overlays |
| History | My Practice and ledger-backed rhythm | Reuse canonical records and their saved local dates; no historical timezone relabeling |
| Content | Private immutable masters, source versions, rights, transcript and glossary versions | Extend with native annotations, teaching segments and candidates |
| Approvals | Revision-bound transcript/quote/render reviews | Add language-qualified reviewer and explicit integrity evidence gates |
| Rendering | Deterministic, bounded local FFmpeg, approved captions, durable jobs | Keep approved native boundaries through enqueue, worker and export checks |
| Analytics | Hub contract envelope; no completed R6 ingestion plane | Keep diagnostic metrics separate from notification outbox; no invented production KPIs |
| Notifications | Existing consent and dispatch rails | No Phase A reminder dispatch; preferences do not enable consent |
| Localization | Existing supported locale catalogue | Preserve catalogue; source language is separate from UI language |
| HH/AppJi | Existing confidential and outreach screens | No new screen or personalization input |

Architectural clarification: nurturing is owned by core domain/database, because its authoritative data is the existing practice ledger. The Hub remains unable to read core tables. These are additive core-owned tables, not a relaxation of the Hub database boundary.

Release dependencies: real 20 Telugu + 5 Kannada + 5 Tamil discourse corpus, authorized native reviewers, approved provider contracts and account eligibility. Synthetic tests cannot satisfy that benchmark. B–D nurturing workflows, autonomous publishing and production rollout remain outside the delta's initial implementation scope.
